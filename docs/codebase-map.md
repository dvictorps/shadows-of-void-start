# Codebase Map

A fast tour for an agent dropped into this repo. Points to where each domain lives so you can grep with intent instead of with hope.

For game design rules (what stats mean, what's allowed where, why), read [CONTEXT.md](../CONTEXT.md). For project guidelines (tech stack, lint and scaling rules, item design decisions), read [CLAUDE.md](../CLAUDE.md). For task recipes ("how do I add a modifier?"), read [docs/playbooks/](./playbooks/).

### `src/game/items/lexicon/` — naming data

Item display names compose at render time from `(nameBase, nameModifier)` tuples on each template. Two locales today (en, pt) sharing a single contract in `types.ts`. Adding a new locale = one new file under this directory.

| File              | Role                                                                                                                                                                                     |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `template-ids.ts` | Literal-union sources of truth: `TemplateBaseId` (~55 bases) and `TemplateModifierId` (~80 modifiers). Templates and lexicons reference these unions — missing entries fail at compile.  |
| `types.ts`        | `ItemNameLexicon` interface. `bases` keyed by `TemplateBaseId`, `modifiers` keyed by `TemplateModifierId`, `prefixForms`/`suffixPhrases` keyed by `PrefixModifierId`/`SuffixModifierId`. |
| `en.ts`           | English entries. Bases as `{ name: string }`. Modifiers as flat strings.                                                                                                                 |
| `pt.ts`           | Portuguese entries. Bases as `{ name, gender: "m" \| "f" }`. Modifiers as `string` (invariant phrase) or `{ m, f }` (gendered adjective).                                                |

See `docs/playbooks/i18n-which-system.md` for the broader decision tree (paraglide vs lexicon vs `mod-i18n.ts`).

### `src/game/stats/compute.ts` — the stat engine

The spine of every gameplay calculation. Read this if you're touching anything that reads character stats. Pure function, fixed-point cascade for broken-state detection, applies a single switch per modifier id.

### `src/game/stats/dps.ts` — DPS estimator

Single source of truth for the "if all hits land" damage-per-second number rendered in `StatusCard` and `ShowStatsModal`. Includes `%increased` pools, `gainAsExtraSpell` (spell path), and the crit factor (`baseCritMultiplier + bonusCritMultiplier` scaled by avg per-swing crit chance). Tests in `dps.test.ts`.

## `src/server/` — Worker backend (D1 + Better Auth + tRPC)

The whole backend ([ADR 0009](./adr/0009-cloudflare-d1-trpc-backend.md)): schema, auth and every game procedure, one tRPC sub-router per domain. The client calls it through `src/integrations/trpc/client.ts` (see `src/lib/` below for the cache helpers). Server code imports `src/game/*` through the `#/` alias. Recipe for a new procedure: [playbooks/adding-a-procedure.md](./playbooks/adding-a-procedure.md).

| File                                          | Concern                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `db/game-schema.ts`                           | Game tables: `characters` (one row holds the character, its combat state and progression, plus the zone bag as a JSON column), `items` (inventory, equipped, stash, told apart by `locationKind`), `leaderboard_snapshot`. JSON columns typed with `$type<>()` from `src/game`. Indexes kept minimal because of the D1 Free write quota: read the header comment before adding one. Re-exports `StashMode` / `stashModeOf` (`src/game/inventory/stash-mode.ts`) |
| `db/auth-schema.ts`                           | Better Auth tables (`user`, `session`, `account`, `verification`). `user.role` is the account role                                                                                                                                                                                                                                                                                                                                                              |
| `db/schema.ts`, `db/client.ts`                | Schema barrel; the shared Drizzle instance on `env.DB` (`casing: "snake_case"`, same as `drizzle.config.ts`) and `batchAll` (one atomic batch, or nothing for an empty list)                                                                                                                                                                                                                                                                                    |
| `auth.ts`                                     | Better Auth on the Drizzle adapter: email + password, 5-minute cookie cache, `role` as a non-input additional field, `cf-connecting-ip` for the rate limiter                                                                                                                                                                                                                                                                                                    |

| `item-reads.ts`                               | Location filters every item write repeats in its WHERE (`inInventoryOf`, `equippedOf`, `inStash`), `loadEquipped`, `loadInventorySlots`, `loadInventoryItem` / `assertInventoryItem`                                                                                                                                                                                                                                                                            |

**Pure decisions the procedures call** (unit-tested, no IO): `src/game/classes/new-character.ts`, `src/game/items/equip-resolution.ts`, `src/game/loot/bag.ts`, `src/game/world/zone-actions.ts`, `src/game/combat/record-kill.ts`, `src/game/stats/cache.ts`, `src/game/vendor/purchase.ts`, plus the older `combat/kill.ts`, `potion.ts`, `vitals.ts`.

**Schema changes:** edit `db/*-schema.ts`, run `pnpm db:generate`, then `pnpm db:migrate:local` / `db:migrate:staging` / `db:migrate:production`. Never hand-edit `drizzle/`.

**Environments:** `wrangler.jsonc` has a top level (local `pnpm dev`, local D1 under `.wrangler/`) plus `staging` and `production`. The Cloudflare Vite plugin picks the environment at build time from `CLOUDFLARE_ENV` in `.env.staging` / `.env.production`, so deploy with `pnpm deploy:staging` / `pnpm deploy:production`, not `wrangler deploy --env`. Local secrets live in `.dev.vars` (template: `.dev.vars.example`).

**Release flow:** feature PRs merge into `dev`; staging is deployed by hand from any branch. A release is `dev` → `master`, then `pnpm db:migrate:production` (if `drizzle/` changed) and `pnpm deploy:production` from `master`. Nothing deploys on push; production deploys need the owner's go-ahead. Production runs at `https://shadows-of-void-production.dvictorps.workers.dev`, staging at `https://shadows-of-void-staging.dvictorps.workers.dev`.

---

**Convention — testing a new server-authoritative mutation.** Extract the deterministic decision into a pure `src/game/` function and unit-test it; keep the procedure a thin auth/IO/randomness wrapper. The tRPC procedures (`src/server/`) are also covered end to end by integration tests against a local D1 (see the `src/server/` section and [playbooks/adding-a-procedure.md](./playbooks/adding-a-procedure.md)). Reference examples, all under `src/game/combat/`: `recordKill` → `kill.ts` / `record-kill.ts`, `consumePotion` → `potion.ts` (`resolvePotionUse`), `syncHp` → `vitals.ts` (`clampVital` / `resolveVitalSync`).

| `useCombatLoop.ts`         | State-machine orchestrator (search → engaged → victory, rare/boss intros, camps, incense, boss-node gauntlet). ## `messages/` and `src/paraglide/`

- **`messages/pt.json`** + **`messages/en.json`** are the source — edit these, paraglide regenerates `src/paraglide/messages.js` on the next dev run.
- Import with `import { m } from "#/paraglide/messages"`. Call as `m.key_name({ param })`.

- `src/paraglide/` is generated — don't hand-edit. `oxlint.config.ts` and `.oxfmtrc.json` exclude the directory from lint/format so it never appears in diffs.
